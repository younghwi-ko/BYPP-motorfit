# Excel 재현 모드의 범위 탐색

## 모드와 생성 규칙

- 제작 후보 모드: 기존 정수 mm·5 mm 간격과 자동 탐색 결과를 유지합니다.
- Excel 재현 모드: Do·do·Lo의 입력 최소·최대값을 보존하고, 각 최소값에 정수 0, 1, 2, … mm를 더해 최대값 이하의 값만 생성합니다. 제작 모드의 5 mm 제약과 자동 범위 확장을 적용하지 않습니다.
- `40.5~42.5`는 `40.5, 41.5, 42.5`, `40.5~42.2`는 `40.5, 41.5`입니다. 임의의 끝점을 추가하거나 소수 시작값을 반올림하지 않습니다.
- 최소=최대이면 해당 치수는 한 값입니다. 세그먼트 수는 두 모드 모두 입력한 양의 정수 범위를 1씩 증가시킵니다. 역전 범위는 입력 오류입니다.
- 전체 후보 수 추정과 동기·비동기 엔진은 동일한 생성 함수를 사용하며, Worker가 범위를 단일 조합으로 축소하지 않습니다.

## 정밀 계산 제한과 성능

Excel 상세 설정의 `정밀 계산 최대 후보 수`로 `maxCandidateCount`를 직접 조절합니다. 화면 기본값은 기존과 같은 200개이며, 정확히 표현 가능한 양의 안전한 정수(1~9,007,199,254,740,991)만 허용합니다. 0·음수·소수·비유한 수는 오류이며 자동 반올림하거나 무제한으로 바꾸지 않습니다. 엔진 API에서 미지정한 경우의 기존 기본 상한은 2,000개입니다.

후보 생성과 정밀 평가는 다릅니다. 상한은 입력 범위나 전체 조합 수를 줄이지 않습니다. Excel은 질량 상한 전처리 후 범위 나열 순서(Do → do → Lo → 세그먼트)의 앞부분부터 상한 개수까지 평가합니다. 형상 유효성은 정밀 평가 시도에서 검사하므로 전처리 후 대상이 모두 유효한 형상이라는 뜻은 아닙니다. 최종 후보 판정·정렬과 이 선택 순서는 변경하지 않습니다.

다음 집계를 화면·저장 metadata·CSV/JSON·인쇄 리포트에서 같은 값으로 사용합니다.

| metadata 필드 (`precisionEvaluation`) | 의미 |
| --- | --- |
| `totalCombinations` | 입력 범위의 전체 조합 수 |
| `eligibleCandidates` | 전처리 후 정밀 계산 대상 수(상한 적용 전·정밀 형상 검증 전) |
| `attemptedCandidates` | 실제 정밀 평가 시도 수. 형상 검증 탈락·계산 실패도 포함 |
| `excludedByLimit` | 상한 때문에 미평가된 대상 수. 형상 탈락·계산 실패와 중복하지 않음 |
| `maxCandidateCount`, `limited` | 적용한 상한과 실제 제한 여부 |
| `selectionOrder`, `scope`, `note` | 범위 순서·평가 범위·해석 안내 |

완료 결과에서는 `eligibleCandidates = attemptedCandidates + excludedByLimit`입니다. 상한이 적용되면 `truncated: true`, `scope: evaluated-subset`이며, 대표·참고 후보와 집계는 평가한 일부 후보 기준입니다. 입력 범위 전체의 최상위 후보나 후보 부재를 뜻하지 않습니다. 상한이 충분하면 `scope: all-preprocessed-candidates`로 표시하지만 전역 최적해·안전 판정은 여전히 아닙니다.

상한을 늘리면 같은 범위의 나중 후보도 평가됩니다. 목록 표시 행 수와 정밀 평가 시도 수는 별개입니다. 정밀 상한은 전체 범위 열거 비용·메모리까지 제한하지 않으며, 상한을 늘리면 계산 시간과 결과 메모리 사용량이 증가할 수 있습니다. Worker 진행률·취소·동일 입력 재계산은 유지됩니다.

## 저장·내보내기와 출처

- 모드 전환 시 입력 범위를 유지하면서 적용 간격을 1/5 mm로 기록합니다. 모드·범위·간격·정밀 상한이 달라지면 기존 결과는 `재계산 필요` 상태가 됩니다.
- 결과의 `metadata.input`과 `searchEnvelope`에 실제 적용 범위·간격·세그먼트 범위를 기록합니다. Excel CSV/JSON의 입력값도 완료 당시 metadata를 사용하므로 입력을 수정해도 과거 결과의 출처가 바뀌지 않습니다.
- 저장 이력·JSON 백업·복원·재내보내기는 해당 snapshot을 보존합니다. 인쇄용 리포트에도 실제 범위·간격과 정밀 상한·제한 여부를 표시합니다.
- 입력 상한을 변경해도 재계산 전 저장·내보내기는 완료 당시의 상한과 정밀 평가 집계를 사용합니다. `metadata.precisionEvaluation`과 `search.precisionEvaluation`은 동일한 요약입니다. 이전 저장 결과에 이 요약이 없으면 새 집계를 임의로 만들지 않습니다.
- 범위 생성 계약 변경을 구분하기 위해 엔진 버전은 `candidate-search-2`입니다. SRM/Excel·GSRM 기준 버전과 AN 카탈로그 버전은 그대로입니다. 이전 저장 결과를 자동으로 새 결과로 덮어쓰지 않습니다.
- 목표 추력 공란은 Worker에서도 그대로 유지하며, 목표 추력 기반 지표를 임의의 기본값으로 계산하지 않습니다.

## 회귀 검증

검증 코드는 [단위 테스트](../tests/excel-range.test.ts)와 [실제 Worker E2E](../e2e/excel-range.spec.ts)에 있습니다.

- 정수 `Do 40~42 / do 10~12 / Lo 78~80 / 세그먼트 1~2`: 예상 치수 목록 및 54조합 대조.
- 소수 시작·비정렬 최대값: 24조합, 상한 바로 아래 경계, 소수 원본 정밀도 보존.
- `45×15×80/2` 단일 Excel 기준 케이스의 기존 질량·압력 기준값 재현.
- 제한 적용 시 전체 조합·범위 보존, 비정수/역전 세그먼트 오류, 결정성, 진행률·취소 후 재계산.
- CSV/JSON 실제 다운로드, 저장·삭제·JSON 백업 복원·저장 결과 재내보내기, 인쇄용 DOM·`window.print()` 호출 stub 확인, 390px 입력·실행.

인쇄 테스트는 실제 PDF 파일 저장을 뜻하지 않습니다. 이 기능은 교육·설계 검토용이며, 전역 최적해·하드웨어 안전성·제작·점화 승인을 제공하지 않습니다.

Windows 로컬 production `http://127.0.0.1:4325`와 격리된 Playwright 컨텍스트를 사용했습니다. 실행 환경은 Node.js `v24.22.1`, pnpm `11.25.0`, Playwright `1.55.1`입니다. 기존 사용자 브라우저 데이터와 이전 검증 기록은 변경하지 않았습니다.

최종 실행의 실패·SKIPPED는 0건입니다. 성능 spec은 전체 E2E에 포함되어 별도 `pnpm test:performance`는 실행하지 않았습니다. 중간 검증에서는 신규 선택자의 단위 접미사와 테스트 입력 fixture를 바로잡았고, 소수 차감 경계 보강 후 최종 빌드로 전체 E2E를 재실행했습니다. 기존 수치·상태 기대값을 완화하지 않았으며, 기존 테스트 변경은 엔진 버전 단언 2곳을 `candidate-search-2`로 맞춘 것뿐입니다.

E2E의 `FORCE_COLOR`/`NO_COLOR` 출력 색상 경고와 느린 파일 안내(기존 `motorfit.spec.ts` 9.2분)가 있었습니다. 이는 lint 경고나 계산 실패가 아닙니다. 일반 Chrome 수동 QA와 실제 PDF 파일 저장을 이번에 새로 수행한 것으로 기록하지 않습니다.

### 정밀 상한 조절 보강 검증 (2026-10-30)

기본 상한 200을 유지하고 사용자가 입력한 값을 Worker에 전달합니다. 아래 고정 범위를 변경하지 않고 상한만 바꿔 대조했습니다.

- 입력: 목표 질량 0.3956 kg, 허용 압력 4.1 MPa, 목표 추력 공란, 질량 허용 오차 0.001 kg.
- 범위: Do 45~46 / do 15~15 / Lo 78~80 mm, 세그먼트 2. 모두 기존 Excel 1 mm 규칙입니다.

관련 브라우저 검증은 로컬 production `http://127.0.0.1:4327`의 격리된 Playwright 컨텍스트에서 수행했습니다.

이번 보강에서는 전체 E2E·성능 spec을 다시 실행한 것으로 기록하지 않습니다. 관련 검증은 데스크톱·390px 상한 입력과 오류, 뒤쪽 후보 평가, 재계산 필요, 저장·백업·복원·CSV/JSON·인쇄용 DOM 일치, 600개 상한으로 취소 후 동일 범위 재계산을 포함합니다. 이전 저장 결과는 `truncated` 표식으로 부분 평가를 안내하되 누락된 상세 집계를 생성하지 않는 것도 확인했습니다. 기존 이력 도구가 결과 영역에 표시되는 흐름에 맞춰 호환성 테스트 절차를 구성했습니다.

최종 실행의 실패·SKIPPED는 0건이며, Node의 출력 색상 설정 경고가 있었습니다. 계산식·판정·정렬·1 mm 생성·5 mm 제작 탐색과 기준 데이터는 변경하지 않았습니다. 인쇄는 `window.print()` stub과 리포트 DOM 확인이며, 실제 PDF 저장·일반 Chrome 수동 QA나 하드웨어 검증을 새로 수행한 기록이 아닙니다.
