# 제작·Excel 모드의 탐색과 판정 일관성

## 변경 이유와 범위

2026-10-31, 수정 전 `ba37136a6ee480c912b2174628353d7a1aa2e1a3`의 production 빌드를 격리된 Playwright Chromium에서 실행했습니다. 사용자 브라우저 저장소는 사용하지 않았습니다.

- 상세 설정 버튼이 `automaticMode`를 해제했고, 실행 경로는 이 값에 따라 연소시간 필터를 덮어썼습니다. 설정을 펼치기만 해도 `재계산 필요`가 표시됐습니다.
- 0.4 kg / 4 MPa / 목표 추력 공란의 제작 자동 결과는 조건부 2개, 대표 `45×10×75/2`였습니다. Excel은 범위 나열 앞 200회를 평가해 조건부 0개, 참고 `41×10×82/2`(0.3561582372108336 kg)를 표시했습니다.
- 두 모드는 실제 범위·세그먼트·간격·예산이 달랐습니다. 같은 목표 입력만으로 같은 후보 집합이 되지는 않습니다.

수정 후 상세 설정 열기·닫기와 후속 행동의 설정 열기는 표시만 바꿉니다. 제작 자동/수동 범위 선택, 연소시간 필터 체크는 별도 입력입니다. 기본 연소시간 필터 비활성은 기존 제작 자동 결과를 보존합니다. 필터를 활성화하면 기존 목표 시간·시간 허용 오차를 그대로 적용하며 새로운 임계값을 만들지 않습니다. 기존 입력에 필터 값이 없다면 이전 자동/수동 실행의 실제 의미를 복원합니다. 저장된 완료 결과는 다시 판정하거나 덮어쓰지 않습니다.

Excel 정밀 대상은 전체 질량 상한 전처리 대상에서 **목표 질량 절대 오차 순**으로 선정합니다. 동률은 Do, do, Lo, 세그먼트 오름차순입니다. 질량 근접 정밀 선정과, 평가 완료 후의 기존 후보 판정·정렬은 별개입니다. 제작 5 mm, Excel 소수 최소값 기준 1 mm 생성과 상한 자체는 변경하지 않습니다. Excel의 기존 정밀 형상 검증 시점도 유지하므로 전처리 대상 수는 유효 결과 수가 아닙니다.

이 선정 계약 변경을 `candidate-search-3`으로 구분합니다. SRM/Excel/GSRM 계산식·기준 데이터·AN 카탈로그·질량/압력/추력 판정 임계값은 변경하지 않았습니다. 이전 엔진 결과는 기존 버전 경고와 저장 snapshot을 유지합니다.

## 공통 후보와 표시 조건

- 정렬된 작은 범위 Do 40~45, do 10~15, Lo 75~80 mm, 세그먼트 1~2에서 5 mm 16개 후보가 1 mm 432개 후보에 모두 포함됩니다. 동일 목표·물성·필터에서 공통 후보의 원본 계산 객체와 판정·사유를 비교합니다. 목표 추력 입력/미입력 및 시간 필터 활성/비활성의 네 조합을 포함합니다.
- 0.4 kg / 4 MPa의 동일 후보 `45×10×75/2`는 두 모드에서 위 제작 대표 수치와 동일합니다. 시간 필터를 껐을 때 조건부, 목표 2.1767 s ± 0.03 s를 명시적으로 켰을 때 연소시간 사유로 탈락합니다. 계산값은 변하지 않습니다.
- 설정 토글 전후 계산 조건·후보 목록·집계가 같고, 동일 입력 재실행도 같습니다. 필터·탐색 방식·상한을 직접 바꾸면 재계산 필요 상태가 됩니다.
- 완료 결과의 실제 범위·선정 순서·상한·필터를 한 영역에서 표시합니다. 결과 상세·저장·CSV/JSON·인쇄는 완료 당시 `metadata.input`을 사용합니다. 재계산 전 입력 변경으로 과거 결과의 조건을 바꾸지 않습니다.

PowerShell에서는 `$env:BASE_URL='http://127.0.0.1:4327'; pnpm test:e2e`로 실행했습니다. 전체 E2E에 `motorfit.performance.spec.ts`가 포함돼 별도 성능 명령은 중복 실행하지 않았습니다. 해당 spec은 24.8초에 통과했으며 기존 취소 응답 30초 미만·취소와 재계산 흐름 180초 미만 기준을 변경하지 않았습니다. 이 24.8초는 전체 spec 실행 시간이며 순수 계산 시간은 아닙니다.

기존 기준 예시·8개 케이스·2 kg·0.763 kg, GSRM/AN 241개, RPA/Fusion, 저장·복원·실제 CSV/JSON 다운로드, 인쇄용 DOM·`print` 호출, 취소·재계산, 민감도·자체 점검, 390px 상호작용이 포함됐습니다. 공통 후보 검증은 [단위 테스트](../tests/mode-consistency.test.ts), 초기 상태·토글·모바일·리포트는 [브라우저 테스트](../e2e/mode-consistency.spec.ts), 상한과 저장 snapshot은 [Excel E2E](../e2e/excel-range.spec.ts)에서 재실행할 수 있습니다.

중간 실행에서는 신규 선택자의 단위 접미사 누락과 CPU 경합·실행 환경의 장시간 정지로 시간 초과가 발생했습니다. 선택자를 수정하고, 네 필터 조합을 각각 독립 테스트로 나누되 후보 범위·수치·판정 단언은 유지한 뒤 최종 검증을 순차 실행했습니다. 기존 테스트의 시간 기준·골든 수치·판정 기대값을 완화하지 않았습니다. Playwright의 색상 환경변수 충돌 경고와 느린 spec 안내는 제품 오류와 구분합니다.

인쇄 검증은 인쇄용 DOM과 `window.print` 호출 stub 검증이며 실제 PDF 파일 저장이나 하드웨어 시험을 뜻하지 않습니다. Vercel 설정과 배포 작업은 수행하지 않았습니다.
